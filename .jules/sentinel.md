## 2024-06-25 - Prevent Exception Detail Disclosure in HTTPException
**Vulnerability:** The `scheduled_snapshot_job` endpoint in `backend/src/routers/internal.py` was catching `Exception as e` and directly returning `str(e)` to the client inside an HTTP 500 error response.
**Learning:** This practice can expose sensitive system details, such as raw database queries, stack traces, or internal server configurations to end-users or potential attackers, violating the principle of least privilege and fail securely.
**Prevention:** Always log the full exception details internally (e.g., `logger.error("...", exc_info=True)`) to maintain observability and debugging capabilities, while returning a generic, safe error message to the client (e.g., "An internal server error occurred"). When updating the exception catch block, remember to use `except Exception:` instead of `except Exception as e:` if `e` is not used in the response, to avoid linting errors like F841 (unused variable).

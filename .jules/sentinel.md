## 2024-10-27 - [HIGH] Prevent Timing Attack and Information Disclosure in Internal Tasks
**Vulnerability:** The internal snapshot scheduler endpoint used a direct string comparison (`!=`) for verifying the secret header, exposing it to timing attacks. Additionally, unexpected errors were returning the raw stack trace/error string to the user via FastAPI's `HTTPException`, causing information disclosure.
**Learning:** Python's `secrets.compare_digest` must be used for constant-time comparison of secrets. Furthermore, when dealing with FastAPI dependencies like `Header(None)`, `None` values must be explicitly handled before calling `compare_digest` as it throws a `TypeError` if a `None` value is passed, which could lead to a 500 error instead of the intended 403 Forbidden. We must also be careful not to leak internal exception details via HTTP APIs.
**Prevention:** Always use `secrets.compare_digest` for validating authentication tokens, API keys, or webhooks. Validate inputs explicitly (e.g., checking for `None`) before passing them to native cryptographic functions. Always wrap generic exceptions and return sanitized, user-friendly error messages rather than raw exception strings in HTTP responses.

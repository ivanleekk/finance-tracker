## 2024-06-10 - [Sentinel] Addressed Information Leakage and Timing Attack Vulnerability in Scheduler Endpoint
**Vulnerability:** A missing scheduler secret during internal endpoints configuration would leak the exact expected environment variable name via `str(e)` in an HTTP 500 `detail`. In addition, simple string equality (`!=`) when comparing header secrets exposed the endpoint to potential timing attacks.
**Learning:** Hardcoding standard `!=` comparisons in security contexts like auth token or scheduler secret verifications leaves systems open to sophisticated but effective timing attacks. Furthermore, catching a generic `Exception as e` and directly returning it to the user bypasses failing securely.
**Prevention:** In Python endpoints handling authorization tokens or scheduler secrets, utilize `secrets.compare_digest` combined with checking for `None`. Ensure `except Exception` blocks fail securely, replacing sensitive stack details with generalized error strings.

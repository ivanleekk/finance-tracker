## 2025-05-28 - [Timing Attack and Information Disclosure in Internal Router]
**Vulnerability:** The internal scheduling endpoint `verify_scheduler_secret` used a standard string equality operator `==` to check the `SCHEDULER_SECRET` header, which is susceptible to timing attacks. Additionally, the `scheduled_snapshot_job` endpoint leaked raw exception strings to the client via `str(e)`.
**Learning:** Even internal or backend-to-backend endpoints require rigorous security checks, especially around secret validation, to prevent side-channel attacks. Catch-all `except Exception as e:` blocks are a common vector for accidental information disclosure if the raw error is returned in an HTTP response.
**Prevention:** Always use `secrets.compare_digest()` (after explicitly checking for `None` values) for comparing any secret, token, or password. Implement a strict policy of sanitizing error responses to return generic, user-friendly messages instead of raw internal exceptions.

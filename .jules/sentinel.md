
## $(date +%Y-%m-%d) - Prevent Timing Attacks and Information Disclosure in Internal Router
**Vulnerability:** The internal router's `verify_scheduler_secret` endpoint was susceptible to timing attacks due to the use of a standard string equality operator (`!=`) for verifying the `x_scheduler_secret`. In addition, the global exception handler in the `scheduled_snapshot_job` endpoint leaked internal application state by passing the raw exception trace (`str(e)`) to the `detail` parameter of the `HTTPException` returning a `500 Internal Server Error`.
**Learning:** Even internal endpoints meant only for cron jobs or scheduling systems must be secured against side-channel timing attacks when verifying authentication tokens or secrets. Additionally, it is critical to ensure that global exception handlers do not bubble raw traceback/exception details up to the client layer.
**Prevention:** Always use `secrets.compare_digest` for validating authentication tokens, API keys, or secrets to guarantee constant-time execution. Ensure that generic user-facing error messages (e.g., "An internal server error occurred") are used in catch-all exception blocks, whilst retaining detailed exception logging securely on the server side.

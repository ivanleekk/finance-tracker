## 2024-06-07 - [Timing Attack & Info Disclosure in Scheduler Endpoint]
**Vulnerability:** The internal scheduler endpoint (`/internal/tasks/daily-snapshot`) verified the scheduler secret using standard string comparison (`!=`) instead of constant-time comparison, making it vulnerable to timing attacks. Furthermore, the catch-all exception handler in `scheduled_snapshot_job` returned `str(e)` in the 500 error response, leaking potentially sensitive stack traces or internal configuration errors to the client.
**Learning:** Even internal-facing endpoints protected by secrets need robust timing attack mitigation (`secrets.compare_digest`), as network timing differences can still be measured. FastAPI's generic HTTPExceptions should never expose raw exceptions, especially unhandled `Exception` blocks.
**Prevention:** Always use `secrets.compare_digest` for token/secret comparison. When handling exceptions, log the raw exception internally using a logger, but return a generic, sanitized string (e.g., "An internal server error occurred") to the client via `HTTPException`.

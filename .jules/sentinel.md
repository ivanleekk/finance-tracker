## 2025-05-21 - [High] Timing attack in secret verification and info disclosure in exception handling
**Vulnerability:** The scheduler secret verification in `backend/src/routers/internal.py` used a standard string comparison (`!=`), which is vulnerable to timing attacks. Additionally, the backend was directly passing `str(e)` in `HTTPException` detail fields for `internal.py` and `portfolio.py`, leading to potential information disclosure of stack traces or internal implementation details.
**Learning:** When comparing secrets, tokens, or passwords, always use `secrets.compare_digest` to perform a constant-time comparison. When doing so with optional `Header(None)` dependencies, explicitly handle `None` values to avoid `TypeError`. Furthermore, never expose raw exception details directly to the client; log them internally and return generic, safe error messages to prevent info disclosure.
**Prevention:** Use `secrets.compare_digest` with explicit `None` checking for all secret comparisons. Sanitize all `HTTPException` detail messages by returning generic messages while logging the raw exceptions server-side.

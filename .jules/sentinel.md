## 2025-02-28 - Information Disclosure via str(e) in HTTP Exceptions and Timing Attack Vulnerability in Scheduler Secret Verification
**Vulnerability:** Fast API routes returning full exception details (`str(e)`) in `HTTPException` detail, enabling attackers to deduce backend functionality via data leaks. Also, `!=` operator usage for string comparison instead of `secrets.compare_digest` in scheduler secret verification route exposed the system to timing attacks.
**Learning:** Returning `str(e)` on broad `Exception` clauses often cascades raw database and system errors down to the client. Python's default `==` and `!=` evaluation short-circuits to allow string-matching latency side-channel leaks when validating credentials directly.
**Prevention:** Always use generic response details when re-raising `HTTPException` inside overarching `except Exception` blocks to prevent exposure of internal state. Always utilize `secrets.compare_digest` to perform constant-time evaluations of tokens.

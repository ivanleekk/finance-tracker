## 2025-02-27 - [Information Leakage & Timing Attack in Snapshot Job]
**Vulnerability:** The internal `/tasks/daily-snapshot` endpoint was susceptible to two vulnerabilities: 1) a timing attack due to using `!=` for comparing a secret token, and 2) information disclosure because it exposed the raw exception `str(e)` in an `HTTPException` detail.
**Learning:** Python's standard `!=` operator short-circuits, enabling timing attacks on secrets. Additionally, direct dependency injection like `Header(None)` means `x_scheduler_secret` could be `None`, which causes `secrets.compare_digest` to raise a `TypeError` if not checked first. Finally, wrapping `str(e)` in HTTP responses leaks stack traces and environment states to clients.
**Prevention:** Always use `secrets.compare_digest` for security tokens, and explicitly check for `None` before comparison when values are optional. Never pass `str(e)` to client-facing HTTP exceptions; log the exception internally and return a generic error.

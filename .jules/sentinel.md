## 2024-05-18 - Fix timing attacks and information disclosure
**Vulnerability:** Fast string comparisons (`!=` or `==`) were used for secrets (like scheduler keys) instead of constant-time checks, leading to timing attacks. Also, uncaught exception details (`str(e)`) were passed to `HTTPException(detail=...)`, leading to information disclosure.
**Learning:** `secrets.compare_digest` must be used for any token, secret, or password comparison. However, since headers can be optional, the `x_scheduler_secret` value can be `None`. `secrets.compare_digest(None, expected)` raises a `TypeError`. We must explicitly handle `None` values first. Furthermore, to prevent leaking internal stack traces, we shouldn't send raw exception details back to the client.
**Prevention:** Use `secrets.compare_digest` when comparing secrets. Ensure inputs to `compare_digest` are strings and not `None`. Avoid returning `str(e)` in error responses; use generic error details while logging the actual exception message locally.

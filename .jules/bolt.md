## 2024-05-18 - Time-Series Chart Data Aggregation
**Learning:** In a dashboard or analytics heavy app, computing running balances or aggregating time-series data dynamically in a render loop via nested filters/sorts (e.g. `arr.map(() => accounts.map(() => history.filter().sort()[0]))`) quickly becomes a catastrophic main-thread bottleneck, causing the UI to freeze as historical dataset sizes grow (e.g. `O(D * A * H log H)`).
**Action:** When aggregating multi-dimensional time-series data for chart render loops, always use an O(N) single-pass approach: first extract and sort all unique dates (once), then iterate chronologically over those dates using hash maps to track running state variables (like `accountLatestBalances`). This avoids doing heavy array operations recursively on every data point.
## 2025-02-12 - Avoid O(N log N) sorts for finding extremum
**Learning:** Copying and sorting an entire array of objects or strings `[...history].sort((a, b) => a.date.localeCompare(b.date))` just to find the latest date or maximum value is highly inefficient (O(N log N)). Doing this inside React render loops or `useMemo` hooks can cause significant performance bottlenecks, especially with large datasets like daily historical balances. String comparison operations like `localeCompare` are particularly slow when used as sorting callbacks.
**Action:** Always use a single-pass `Array.prototype.reduce()` or a simple `for` loop (O(N)) to find the maximum or minimum value in an array. Also, use standard relational operators (`>` and `<`) instead of `localeCompare` when comparing ISO date strings for faster execution.
